1. Biggest remaining issue: calibration consistency

This is now my #1 improvement.

You have cross-fitted calibration:

Fold 1:
    calibrator trained on other folds
Fold 2:
    calibrator trained on other folds
Fold 3:
    calibrator trained on other folds
Fold 4:
    calibrator trained on other folds

Then you build crossfit_probabilities.

After that you fit another final calibrator on folds 1–4 and determine the final threshold.

The subtle issue is:

threshold is learned from
    cross-fitted calibrator outputs

but test uses
    pooled/final calibrator

Those transformations are not guaranteed to be identical.

Better design

Reserve fold 0 completely.

Then:

Folds 1-4 raw OOF predictions
             │
             ▼
       ONE calibrator
             │
             ▼
   calibrated F1-F4 scores
             │
             ▼
     threshold + margin
             │
             ▼
         Fold 0

Then:

Final model → final calibrator → same threshold

This makes:

calibration
threshold
test inference

more coherent.

I would implement this before touching the model.

2. Your final entity model is underusing the tuning data

This is subtle.

You currently do:

folds 1,2,3 → entity-model fitting
fold 4       → threshold/policy tuning
fold 0       → evaluation

That's statistically clean.

But after determining the gate/cardinality architecture, the final entity classifier still effectively comes from the earlier fit partition.

You could do:

Stage 1:
    folds 1-3 → fit
    fold 4 → tune

Stage 2:
    freeze hyperparameters + thresholds

Stage 3:
    refit entity classifier on folds 1-4

Stage 4:
    fold 0 = final audit

The tricky part is probability-threshold calibration, so I would refit using a calibrated meta-score rather than blindly reusing a probability threshold.

This gives the final meta-model more data without contaminating fold 0.

11. One thing I would now investigate: hard-negative mining may be too concentrated

Your OOF adversarial mining takes the highest-scoring negatives per entity.

That's good, but think about this distribution:

20 negatives/entity
+
5 adversarial negatives/entity

The final training distribution can become disproportionately dominated by:

"things the current model already thinks are matches"

That's useful, but eventually you can over-specialize to the current model's errors.

I would use a mixed hard-negative pool:

40% hardest
30% medium-hard
20% structurally hard
10% random

rather than only top-scoring negatives.

Your existing negative categories already make this possible.

This is a smaller optimization than retrieval.
