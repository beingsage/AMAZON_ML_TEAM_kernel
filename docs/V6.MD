# 🔴 P0 — I found a real bug

## `threshold_search_from_scores()` is not computing per-score positive counts correctly

The problematic part is effectively:

```python
unique_scores, starts, counts = np.unique(
    eligible_scores, return_index=True, return_counts=True
)

true_counts_by_score = np.add.reduceat(
    eligible_labels.astype(np.int64),
    starts
)
```

The problem is:

**`np.unique(..., return_index=True)` sorts `eligible_scores`, but `eligible_labels` remains in the original order.**

So `starts` refer to positions in the **sorted score array**, while you're applying them to the **unsorted label array**.

That means the event sweep can compute the wrong F0.5 for a threshold.

I tested this against a brute-force implementation on random small entity datasets and found a mismatch immediately.

That is a **real optimization bug**.

---

## Fix it like this

Replace that section with:

```python
order = np.argsort(eligible_scores, kind="stable")
sorted_scores = eligible_scores[order]
sorted_labels = eligible_labels[order]

unique_scores, starts, counts = np.unique(
    sorted_scores,
    return_index=True,
    return_counts=True,
)

true_counts_by_score = np.add.reduceat(
    sorted_labels.astype(np.int64),
    starts
)
```

Then your sweep is actually exact.

### Why this matters so much

This function determines:

```text
pair threshold
+
within-entity margin
        ↓
final match selection
```

and therefore directly affects the competition metric.

So before changing any model, **fix this**.

# 🟠 P0 — Your calibration/threshold pipeline is still slightly inconsistent

You've improved this substantially.

Your architecture is now:

```text
OOF
 ↓
cross-fitted calibration
 ↓
threshold
 ↓
independent fold
```

which is good. 

But the final threshold is selected using `crossfit_probabilities` whose fold-specific calibrators differ, while test inference uses one final calibrator.

Conceptually:

```text
Fold 1 → calibrator A
Fold 2 → calibrator B
Fold 3 → calibrator C
Fold 4 → calibrator D

threshold selected from
A + B + C + D

TEST → final calibrator E
```

The scores are approximately comparable, but not guaranteed to be identically calibrated.

### Better design

Use:

```text
Fold 0 = untouched final validation

Fold 1..4
     ↓
nested cross-fit calibration
     ↓
OOF calibrated probabilities
     ↓
threshold selection

Then:
train final model
     ↓
fit ONE final calibrator
     ↓
apply fixed threshold
```

Even cleaner:

```text
raw OOF scores
       ↓
cross-fitted calibration
       ↓
OOF probabilities
       ↓
threshold optimization
```

Then independently:

```text
raw test scores
       ↓
final calibration model
       ↓
same threshold
```

That makes the semantics of the threshold much cleaner.
